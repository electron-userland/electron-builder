feat!: electron-updater sends every update-feed request header and the feed query only to downloads on the feed's origin. With the generic, s3, spaces, r2, keygen, bitbucket, github and gitlab providers, a download on another origin than the feed (scheme, host or port) — an absolute `files[].url` or `packages.<arch>.path` in `latest*.yml`, a GitLab release asset link, and the blockmaps and differential range requests derived from them — is requested with only the headers from `requestHeaders` / `addAuthHeader` that the app's `crossOriginHeaderAllowlist` of `checkForUpdates` allows (see https://www.electron.build/docs/migration/v27-runtime-changes#cross-origin-header-allowlist) and without the feed URL's query string. Such a URL keeps its own query string, so pre-signed URLs work. With every provider, including custom ones, a URL that electron-updater resolves against the feed URL (such as a `files[].url` or a blockmap) gets the feed query only on the feed's origin; as on redirects, an `http` → `https` upgrade of the feed host on the default ports keeps the headers and the query. Downloads on the feed origin get every request header and the feed query, and the old blockmap from an app-set `previousBlockmapBaseUrlOverride` gets every request header on that origin. If your `latest*.yml` points downloads at another origin that needs these headers, serve the files from the feed origin, use pre-signed URLs, or allow the headers for that origin in `crossOriginHeaderAllowlist`. The NSIS web-package differential download uses the same per-download headers as other downloads. Every provider returns its feed URL from `Provider.feedBaseUrl`: the built-in ones return theirs (private GitHub returns the GitHub API, whose asset URLs need its token), and a custom provider whose `feedBaseUrl` is not a URL, `null` included, fails the update check with `ERR_UPDATER_FEED_BASE_URL_NOT_DECLARED` before it gets any request header (see https://www.electron.build/docs/migration/v27-developer-changes#custom-provider-feed-base-url). The first download that does not get the feed query logs a warning once per updater, naming the query parameters and the origins (never their values), with a link to the migration guide. New APIs: `Provider.feedBaseUrl` (required), `HttpExecutor.keepCrossOriginHeaders`, `DEFAULT_CROSS_ORIGIN_HEADERS` and `HttpExecutor.isCrossOrigin`.
