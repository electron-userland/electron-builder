feat(runtime)!: a redirect to another origin, and an electron-updater download or channel file request on another origin than the feed, send only the request headers that two layers choose for that request: the update provider's `Provider.crossOriginHeaders(defaults, request)` first, then the app's `crossOriginHeaders`, which gets the provider's choice as `defaults` (the names of every header of the request when the provider returns `null`) and decides. Every provider implements `crossOriginHeaders` (abstract): the built-in providers return `defaults`, and private GitHub returns `null` for the GitHub API's origin and `defaults` elsewhere; a provider without it fails the update check with `ERR_UPDATER_CROSS_ORIGIN_HEADERS_NOT_CONFIGURED`, naming it, before any request (see https://www.electron.build/docs/migration/v27-developer-changes#custom-provider-cross-origin-headers). `Provider.feedBaseUrl` only fills `request.from`: without a feed URL, `from` is `null` and both layers are asked about every request. `checkForUpdates(options)` and `checkForUpdatesAndNotify(options)` require `{ crossOriginHeaders }` for every app (`CheckForUpdatesOptions`, and `CheckForUpdatesAndNotifyOptions` with an optional `notification`): pass `{ crossOriginHeaders: defaults => defaults }` to send the provider's choice (with a built-in provider, the default list (`Accept`, `Accept-Encoding`, `Accept-Language`, `User-Agent`, `Cache-Control`, `Pragma`, `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Content-Language`)), or a function of the default list and the request (`{ from, to, kind: "redirect" | "request" }`) that returns the header names for that request, or `null` for every header on it; `x-user-staging-id` goes to another origin only when returned. A call without it, and `downloadUpdate()` before such a check, reject with `ERR_UPDATER_CROSS_ORIGIN_HEADERS_NOT_CONFIGURED`; replace `checkForUpdatesAndNotify(notification)` with `checkForUpdatesAndNotify({ crossOriginHeaders, notification })`. Both are called only for another origin (for every request without a feed URL); for a redirect the updater follows, the provider is the one of the latest check, and the app's function of the last check also serves its download and the install of an update marked for the next launch. A throw or a result that is not an array of header names or `null`, from either layer, fails that request with `ERR_UPDATER_INVALID_CROSS_ORIGIN_HEADERS`, naming the layer. builder-util-runtime exports `DEFAULT_CROSS_ORIGIN_HEADERS` and the `CrossOriginRequest` (`from: URL | null`), `CrossOriginHeadersCallback` and `CrossOriginHeadersLayer` types (the first two re-exported by electron-updater); `HttpExecutor` takes a `CrossOriginHeadersCallback` as its constructor argument for its redirects (`crossOriginRedirectHeaders()` returns what they use), `HttpExecutor.keepCrossOriginHeaders(headers, request, crossOriginHeaders)` applies one or an array of layers, and builder-util-runtime has no `addSensitiveRedirectHeader`, `HttpExecutor.removeCrossOriginSensitiveHeaders` or `HttpExecutor.sensitiveHeaderNames`. See https://www.electron.build/docs/migration/v27-runtime-changes#cross-origin-header-allowlist
