feat(runtime)!: a redirect to another origin, and an electron-updater download or channel file request on another origin than the feed, send only the request headers that `crossOriginHeaders` returns for that request. `checkForUpdates(options)` and `checkForUpdatesAndNotify(options)` require `{ crossOriginHeaders }` for every app (`CheckForUpdatesOptions`, and `CheckForUpdatesAndNotifyOptions` with an optional `notification`): pass `{ crossOriginHeaders: defaults => defaults }` to send the default list (`Accept`, `Accept-Encoding`, `Accept-Language`, `User-Agent`, `Cache-Control`, `Pragma`, `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Content-Language`), or a function of the default list and the request (`{ from, to, kind: "redirect" | "request" }`) that returns the header names for that request, or `null` for every header on it; `x-user-staging-id` goes to another origin only when returned. A call without it, and `downloadUpdate()` before such a check, reject with `ERR_UPDATER_CROSS_ORIGIN_HEADERS_NOT_CONFIGURED`; replace `checkForUpdatesAndNotify(notification)` with `checkForUpdatesAndNotify({ crossOriginHeaders, notification })`. The function is called only for another origin, and the one of the last check also serves its download and the install of an update marked for the next launch. A throw or a result that is not an array of header names or `null` fails that request with `ERR_UPDATER_INVALID_CROSS_ORIGIN_HEADERS`. A custom provider whose downloads carry a header off the default list declares `Provider.feedBaseUrl`. builder-util-runtime exports `DEFAULT_CROSS_ORIGIN_HEADERS` and the `CrossOriginRequest` and `CrossOriginHeadersCallback` types (re-exported by electron-updater); `HttpExecutor` takes a `CrossOriginHeadersCallback` as its constructor argument for its redirects, `HttpExecutor.keepCrossOriginHeaders(headers, request, crossOriginHeaders)` applies one, and builder-util-runtime has no `addSensitiveRedirectHeader`, `HttpExecutor.removeCrossOriginSensitiveHeaders` or `HttpExecutor.sensitiveHeaderNames`. See https://www.electron.build/docs/migration/v27-runtime-changes#cross-origin-header-allowlist
