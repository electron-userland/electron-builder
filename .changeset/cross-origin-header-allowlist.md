feat(runtime)!: a redirect to another origin, and an electron-updater download or channel file request on another origin than the feed, send only the request headers on an explicit list. `autoUpdater.crossOriginHeaders` chooses it: a function that gets the default list (`Accept`, `Accept-Encoding`, `Accept-Language`, `User-Agent`, `Cache-Control`, `Pragma`, `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Content-Language`) and returns the header names to send, or `null` to send every header to every origin; `x-user-staging-id` is sent to another origin only when listed. An app that sets `requestHeaders`, calls `addAuthHeader` or uses a custom provider with `fileExtraDownloadHeaders` sets it, e.g. `autoUpdater.crossOriginHeaders = defaults => defaults`, or the update check fails with `ERR_UPDATER_CROSS_ORIGIN_HEADERS_NOT_CONFIGURED`; a result that is not an array of header names or `null` fails with `ERR_UPDATER_INVALID_CROSS_ORIGIN_HEADERS`. A custom provider whose downloads carry a header off the list declares `Provider.feedBaseUrl`. builder-util-runtime exports the default list as `DEFAULT_CROSS_ORIGIN_HEADERS` and the function type as `CrossOriginHeaders`, which `HttpExecutor` takes as its constructor argument for its redirects; `HttpExecutor.keepCrossOriginHeaders(headers, from, to, allowed)` applies a list, and there is no `addSensitiveRedirectHeader`, `HttpExecutor.removeCrossOriginSensitiveHeaders` or `HttpExecutor.sensitiveHeaderNames`. See https://www.electron.build/docs/migration/v27-runtime-changes#cross-origin-header-allowlist
