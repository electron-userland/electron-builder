feat(runtime)!: a redirect to another origin, and an electron-updater download or channel file request on another origin than the feed (`Provider.feedBaseUrl`), send only the request headers that the app's `crossOriginHeaderAllowlist` allows for that request. `checkForUpdates(options)` and `checkForUpdatesAndNotify(options)` require `{ crossOriginHeaderAllowlist }`, or the updater's `crossOriginHeaderAllowlist` property, for every app (`CheckForUpdatesOptions`, and `CheckForUpdatesAndNotifyOptions` with an optional `notification`), either a list of header names or a callback (the `CrossOriginHeaderAllowlist` type). A list (case-insensitive) is exactly what is sent: pass `{ crossOriginHeaderAllowlist: DEFAULT_CROSS_ORIGIN_HEADERS }` (exported by electron-updater) for the default list (`Accept`, `Accept-Encoding`, `Accept-Language`, `User-Agent`, `Cache-Control`, `Pragma`, `Range`, `If-Range`, `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`, `Content-Type`, `Content-Length`, `Content-Encoding`, `Content-Language`), or `[...DEFAULT_CROSS_ORIGIN_HEADERS, "x-tenant"]` to add one. A callback gets the default list as `defaults` and the request (`{ from, to, kind: "redirect" | "request" }`), and returns the header names for that request, or `null` for every header on it. The feed's origin gets every header: private GitHub's feed is the GitHub API, so its token reaches the API's asset URLs, and the storage the API redirects a download to gets only what the app's list or callback allows; a release asset URL on another origin than the API fails with `ERR_UPDATER_ASSET_TOKEN_NOT_ALLOWED` before it is requested unless the list or callback allows `authorization` for that origin. `x-user-staging-id` goes to another origin only when allowed. The updater's `crossOriginHeaderAllowlist` property, of the same type and `null` by default, serves a check without the option and the requests before any check, such as the install at launch of an update marked for the next launch (set it before the app is `ready`); a check's option takes precedence. A call without the option and without the property, or with a value that is neither a list nor a function, emits `error` and rejects with `ERR_UPDATER_CROSS_ORIGIN_HEADERS_NOT_CONFIGURED`, and so does `downloadUpdate()` before such a check; replace `checkForUpdatesAndNotify(notification)` with `checkForUpdatesAndNotify({ crossOriginHeaderAllowlist, notification })`. The allowlist of the last check also serves its download, the redirects the updater follows and the install of an update marked for the next launch; before any check, the property serves them. A list entry that is not a header name, or a throw or a result that is not an array of header names or `null` from the callback, fails that request with `ERR_UPDATER_INVALID_CROSS_ORIGIN_HEADERS`. builder-util-runtime exports `DEFAULT_CROSS_ORIGIN_HEADERS` and the `CrossOriginRequest` and `CrossOriginHeadersCallback` types (re-exported by electron-updater, with `CrossOriginHeaderAllowlist`); `HttpExecutor` takes a `CrossOriginHeadersCallback` as its constructor argument for its redirects, `HttpExecutor.keepCrossOriginHeaders(headers, request, crossOriginHeaders)` applies one, electron-updater's `ProviderRuntimeOptions` has a required `crossOriginHeaders` (a `CrossOriginHeadersCallback`, set by electron-updater to the app's choice, so code that constructs a built-in provider passes on the runtime options it was given), and builder-util-runtime has no `addSensitiveRedirectHeader`, `HttpExecutor.removeCrossOriginSensitiveHeaders` or `HttpExecutor.sensitiveHeaderNames`. See https://www.electron.build/docs/migration/v27-runtime-changes#cross-origin-header-allowlist
