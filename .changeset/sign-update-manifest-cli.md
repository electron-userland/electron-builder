feat: add `electron-builder sign-update-manifest <files..>` to re-sign an edited `latest*.yml` in place without rebuilding. Like `publish` it reads the project configuration (`-c` / `--config`, including `-c.updateManifestSigning.signingKeyFile=...` overrides) and signs with the key(s) the build would use — `updateManifestSigning.signingKey` / `signingKeyFile` per platform, then `ELECTRON_BUILDER_UPDATE_SIGN_KEY(_FILE)` — refusing, like a publishing build, signing keys outside an explicit `updateManifestSigning.publicKey` unless `allowSigningKeyOutsideTrustList` is set, after validating the manifest shape and dropping the old `signature`/`signatures`, keeping every other field; `--verify` checks the existing signatures without writing, with the same check and outcomes as `electron-builder verify` (against `updateManifestSigning.publicKey`, honoring `updateManifestSigning: false` and `allowSigningKeyOutsideTrustList`, and never loading a signing key). Re-signing refuses a manifest whose `sha512` or `size` does not match a listed file (found next to the manifest or in the build output folder, by name or GitHub-safe name, as `electron-builder verify` finds it), since electron-updater rejects such a download; `--rehash` takes both from the files instead, for artifacts a release step changed after the build (for example Linux packages signed separately), and the docs' manual re-sign script does the same where electron-builder cannot run. A manifest that is a symlink is refused rather than followed. `electron-builder verify` now also finds a file a GitHub manifest lists by its safe name under its local name (spaces instead of `-`), so a file changed after the build is reported as changed rather than missing, and a listed file found by its name is no longer reported as matching because an unchanged copy of the original sits elsewhere in the output. `sign-update-manifest` likewise refuses a listed file it cannot find while the searched folders hold other files of the release, and signs without the check (with a warning) only when none are there. A missing key fails with an `InvalidConfigurationError`, and key material is never printed. An unreadable signing key file now fails with an `InvalidConfigurationError` naming its source instead of a raw `ENOENT`.
