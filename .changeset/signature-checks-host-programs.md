fix: electron-builder starts `codesign`, `stapler`, `pkgutil` and Windows PowerShell by absolute path, from `toolsets.executables` or their default locations, for the signature checks of `forceCodeSigning` and `electron-builder verify`, for re-signing the Electron framework after embedding the ASAR integrity digest and for reading the Team ID of nested binaries; the keychain it creates trusts the configured `codesign` and `productbuild`. New `toolsets.executables` keys: `stapler` (located with `/usr/bin/xcrun --find stapler` by default) and `pkgutil` (`/usr/sbin/pkgutil` by default). The signature checks pass `mac.sign.strictVerify` to `codesign --verify` as `true`, `false` or a comma-separated list of the `--strict` keywords `all`, `symlinks` and `sideband`; another value is a configuration error. Reading an Authenticode signature back starts PowerShell without the build's credential variables. `electron-builder verify` uses public keys only: without a packaged app's trust list it verifies update manifests against `updateManifest.publicKey`, and reports them as unverifiable when that is not set; it never loads a signing key. It honors `mas.sign` / `masDev.sign` opt-outs for Mac App Store apps, reads only the app output directories of the targets, and reads an app's `app-update.yml` only as a file inside the app, reporting one that is a symlink out of the app, invalid YAML or not a mapping as a failed check. The Team ID of a signing identity name is parsed in linear time.
