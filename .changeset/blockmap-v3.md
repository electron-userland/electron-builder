feat: `blockmap` option, `"v1" | "v2" | "latest"` (default `"latest"`), selecting the format of the `<artifact>.blockmap` published next to NSIS installers and macOS update zips. `"v2"`, the new default, is a range-fetchable three-level binary block map, so differential updates no longer pay for the whole map on every update. The map is uncompressed with fixed-size tables (header, content-defined super-groups of groups, content-defined groups of blocks, 10-byte per-block records, with 8-byte hashes at every level). electron-updater fetches the header and super-group table with one `Range` request, matches super-groups against its cached previous map, fetches only the group entries of the super-groups that changed, matches those groups and fetches only the records of the groups that changed, then runs the existing block-level plan and download pipeline. Because the map cost grows with the change rather than with the installer, the stored `app.asar` region (`nsis.differentialPackage: "store-asar"`, ideally with `asar.contentAlignment`) uses 512 B / 1 KiB / 2 KiB blocks in `"v2"`, and a block boundary at every packed file. `"v1"` is the gzipped JSON map, byte-for-byte as before. electron-updater tells the formats apart by the file's first bytes, so there is no extra artifact and `latest.yml` is unchanged. electron-updater before 7.0 cannot read `"v2"` and falls back to a full download once; the update it installs brings an updater that can. A format change between two releases costs the same one-time full download. Block maps embedded in an artifact (AppImage, NSIS web installer packages) stay `"v1"`.

electron-updater additionally downloads through COPY gaps smaller than 8 KiB between two changed ranges on single-range hosts such as GitHub and S3 (one request per range there makes re-downloading a few KiB cheaper than an extra request), only up to 256 B on hosts that serve `multipart/byteranges`, and caps `multipart/byteranges` requests at 200 ranges (Apache's `MaxRanges` default; larger `Range` headers exceed common 8 KB header limits). The 7z header of a differential-aware package is now stored as is (`-mhc=off`) and chunked into its own small blocks, so a changed CRC no longer re-downloads the trailing block of the package (5–30 KB on every update). That changes the block boundaries once at the tail of the package (a one-time re-download of its last block).
