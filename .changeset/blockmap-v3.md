feat: block map v3 (`<installer>.blockmap3`) — a range-fetchable three-level binary block map published next to the unchanged `.blockmap` so differential updates no longer pay for the whole map on every update. The v3 map is uncompressed with fixed-size tables (header, content-defined super-groups of groups, content-defined groups of blocks, 10-byte per-block records, with 8-byte hashes at every level); electron-updater fetches the header and super-group table with one `Range` request, matches super-groups against its cached previous map, fetches only the group entries of the super-groups that changed, matches those groups and fetches only the records of the groups that changed, then runs the existing block-level plan and download pipeline. Because the map cost grows with the change rather than with the installer, the stored `app.asar` region (`nsis.differentialPackage: "store-asar"`, ideally with `asar.contentAlignment`) uses 512 B / 1 KiB / 2 KiB blocks in v3 while v2 keeps its default chunking byte-for-byte for older updaters. Older electron-updater versions ignore `.blockmap3`, and a new updater falls back to `.blockmap` whenever the v3 map cannot be fetched or parsed. electron-updater additionally downloads through COPY gaps smaller than 8 KiB between two changed ranges (one request per range on GitHub/S3-class hosts makes re-downloading a few KiB cheaper than an extra request) and caps `multipart/byteranges` requests at 200 ranges (Apache's `MaxRanges` default; larger `Range` headers exceed common 8 KB header limits).

Three more changes to the differential path that the measurements singled out: the 7z header of a differential-aware package is now stored as is (`-mhc=off`) and chunked into its own small blocks, so a changed CRC no longer re-downloads the trailing block of the package (5–30 KB on every update); electron-updater downloads through COPY gaps only up to 256 B on hosts that serve `multipart/byteranges` (the 8 KiB threshold stays for single-range hosts such as GitHub and S3); and the v3 map forces a block boundary at every packed file of a stored asar, so an edit inside one file never changes a block of its neighbour. The first changes the v2 block boundaries once at the tail of the package (a one-time re-download of its last block).
