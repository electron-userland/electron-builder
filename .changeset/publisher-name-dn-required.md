feat(win)!: require every `publisherName` entry to be a distinguished name (DN) (e.g. `"CN=My Company, O=My Company, C=US"`). An explicit `win.sign.publisherName` with an entry that is not a DN (e.g. a bare name) now fails the build with `InvalidConfigurationError` on every signing route (`signtool`, `hsm`, `pkcs11`, a custom `sign` hook, `azure`) before anything is signed, because electron-updater 7 never matches such an entry; `publisherName: null` still opts out. Without `publisherName`, the build now writes the certificate's full subject to `app-update.yml` instead of its Common Name, in the format Windows reports it (the format electron-updater matches against, e.g. `S=` for the state); the build-time checks of an explicit `publisherName` read the subject in the same format. `electron-builder migrate-schema` prints an advisory for an entry that is not a DN. See https://www.electron.build/docs/migration/v27-breaking-changes#windows-publishername-must-be-a-distinguished-name
