feat(win)!: require every `publisherName` entry to be a distinguished name (DN) (e.g. `"CN=My Company, O=My Company, C=US"`). An explicit `win.sign.publisherName` with an entry that is not a DN (e.g. a bare name) now fails the build with `InvalidConfigurationError` on every signing route (`signtool`, `hsm`, `pkcs11`, a custom `sign` hook, `azure`) before anything is signed, because electron-updater 7 never matches such an entry; `publisherName: null` still opts out. Without `publisherName`, the build now writes `CN=<common name>` of the certificate to `app-update.yml` instead of the bare Common Name, with the value quoted the way Windows quotes it in the subject electron-updater matches against, so a renewed certificate with the same CN keeps updates working (set a fuller DN explicitly for a stricter pin); the build-time checks of an explicit `publisherName` read the subject in the format Windows reports it (e.g. `S=` for the state). `electron-builder migrate-schema` prints an advisory for an entry that is not a DN. See https://www.electron.build/docs/migration/v27-build-changes#windows-publishername-must-be-a-distinguished-name
