feat(win)!: require every `publisherName` entry to be the code signing certificate's subject distinguished name (DN) including `CN` and `O` (e.g. `"CN=My Company, O=My Company, C=US"`). An explicit `win.sign.publisherName` with a bare name or a DN without both `CN` and `O` now fails the build with `InvalidConfigurationError` on every signing route (`signtool`, `hsm`, `pkcs11`, a custom `sign` hook, `azure`) before anything is signed, because electron-updater 7 never matches such an entry; `publisherName: null` still opts out. Without `publisherName`, the build now writes the certificate's `CN`, `O` and (when present) `C` to `app-update.yml` instead of its Common Name, and a certificate without an `O` fails the build. The certificate subject is now read in the format Windows reports it (the format electron-updater matches against, e.g. `S=` for the state), both for the derived name and for the build-time checks of an explicit `publisherName`. `electron-builder migrate-schema` prints an advisory for an entry that is not such a DN. See https://www.electron.build/docs/migration/v27-breaking-changes#windows-publishername-must-be-a-distinguished-name
