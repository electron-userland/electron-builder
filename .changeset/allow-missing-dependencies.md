feat: fail builds on missing production dependencies by default. When node-module collection completes and a production dependency could not be resolved (`cannot find path for dependency` / `dependency not found on disk`), the build now fails with an error listing the complete set of missing dependencies, instead of logging warnings and producing a package that breaks at runtime with `MODULE_NOT_FOUND`. Configure via the new `allowMissingDependencies?: boolean | string[] | null` option: `true` restores the previous warn-only behavior, a `string[]` allows only the listed dependency names to be missing (bare package name, or exact `name@version`), and `false`/`null`/omitted (the default) fails on any missing production dependency. Missing optional dependencies (declared in `optionalDependencies`, e.g. `fsevents` on Linux/Windows, or platform-specific packages) are always allowed and never fail the build. Migration: builds that previously "succeeded" while logging `dependency not found on disk` / `cannot find path for dependency` warnings will now fail — fix the underlying installation issue, list the affected dependency names in `allowMissingDependencies`, or set `allowMissingDependencies: true` to keep the old behavior.
