feat!: rename the update-manifest signing option `updateManifest` to `updateManifestSigning` (root, `mac`, `win`, `linux`; the value is unchanged), because `updateManifest: false` read as "no manifest" while it ships unsigned ones: a configuration that still sets `updateManifest` fails with the rename, `migrate-schema` renames it, `sign-update-manifest` now runs the build's check for removed and renamed configuration keys and so rejects it too, and `UpdateManifestSigningOptions` is exported; GitLab publish entries take `tagNamePrefix` (default `"v"`, as on GitHub) instead of `vPrefixedTagName`, which the build rejects; it also names a release without `releaseInfo.releaseName`, and `migrate-schema` rewrites `vPrefixedTagName: false` to `tagNamePrefix: ""` (replacing the alpha behavior that kept it), reads `"false"`, `0` and `null` as `false` on GitHub and GitLab as v26 did, and leaves a JS/TS value that is not a literal for the build to reject; a custom macOS signer moves from `mac.sign` to `mac.sign.sign` (`mas` / `masDev` too), where it receives the signing options next to it as `win.sign.sign` does, and the build rejects a bare one, naming the new place (`-c.mac.sign.sign=…` on the command line); `mac.sign: false` (or `null`) skips signing, of the DMG too, the `mac.sign` options are schema-validated, `sign.identityValidation` is removed (it never had an effect) and `sign.batchCodesignCalls` / `sign.preEmbedProvisioningProfile` now reach `@electron/osx-sign`, and `MacSignConfiguration` is exported; `migrate-schema` moves a string or function signer, folding the v26 signing options next to it in, rewrites a `mas.sign: null` that kept the mac signer from signing the Mac App Store app to `mas.sign.sign: null`, and warns where the signer of a 27.0.0 alpha Mac App Store configuration changes; `snapcraft.core24.buildEnvironment: "lxd" | "multipass" | "host" | "remote"` replaces `useLXD`, `useMultipass`, `useDestructiveMode` and `remoteBuild.enabled`, which the build rejects, the other `remoteBuild` options are read only for `"remote"`, and `migrate-schema` rewrites a configuration that turns on at most one of them; a target's `publish` (deb, rpm, pacman, freebsd, p5p, apk, AppImage, flatpak, snapcraft, appx, msi and msiWrapped over the platform's; nsisWeb over nsis) replaces the inherited one instead of being merged with it, the build warns once per target section where the merge kept a provider, an option or the first provider, `migrate-schema` prints an advisory, and a target's options no longer carry the platform's `publish`
