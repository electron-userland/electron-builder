feat!: Windows update signature verification fails closed and requires a distinguished-name `publisherName` — electron-updater installs an NSIS update only when PowerShell verifies it: an update it cannot verify (PowerShell cannot be started or run, times out, prints unreadable output; before, PowerShell that could not be started or any failure on Windows 7/8 installed it with a warning) is rejected with `ERR_UPDATER_SIGNATURE_UNVERIFIABLE`, a Windows catalog signature is rejected, `powershell.exe` is started by absolute path, the installer path is passed in an environment variable, and non-ASCII output is escaped instead of setting a console encoding (fixing PowerShell Constrained Language Mode in 7.0.0-alpha.8 to alpha.10); a bare common name `publisherName` never matches and fails a build that writes `app-update.yml`, and the derived `publisherName` is the certificate's `CN`, `O` and `C` (builder-util-runtime adds `isDistinguishedName`, `prepareAuthenticodeSignatureExec` and `POWERSHELL_ASCII_ESCAPE_FUNCTION`). Migration: set `win.sign.publisherName` to the `CN`, `O` and `C` of the certificate subject (e.g. `CN=My Company, O=My Company, C=US`), upgrade electron-builder together with electron-updater (electron-builder 26 writes a bare name, whose updates electron-updater 7 rejects), and where PowerShell may be blocked assign a native `verifyUpdateFileAuthenticodeSignature` in your first electron-updater 7 release — see https://www.electron.build/docs/migration/v27-breaking-changes#windows-update-signature-verification-fails-closed
