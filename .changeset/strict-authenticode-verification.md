feat(updater)!: Windows update signature verification fails closed — electron-updater installs an NSIS update only when PowerShell (`Get-AuthenticodeSignature`) verifies it: an update it cannot verify (PowerShell cannot be started or run, times out, or prints unreadable output) is rejected with `ERR_UPDATER_SIGNATURE_UNVERIFIABLE`, and a Windows catalog signature is rejected as invalid unless the app opts in with the new `NsisUpdater.allowCatalogSignature` (default `false`; when `true`, a valid catalog signature is accepted with a warning only when its signer matches `publisherName`). A release can allow it instead with the new `win.allowCatalogSignature` build option (default `false`), which writes `allowCatalogSignature: true` into the `latest.yml` of the `nsis` and `nsis-web` targets; electron-updater honors it only when that manifest's signature was verified against a trusted key (`updateManifestPublicKey`) and ignores it with a warning otherwise. The manifest signature covers it as an extra `allowCatalogSignature:true` line of the `EBUM1` payload only when it is `true`, so manifests without it canonicalize and verify exactly as before, and changing it for a published release means re-signing or republishing `latest.yml`; a signed manifest with a non-boolean `allowCatalogSignature` is rejected. electron-updater 7.0.0-alpha.8 to alpha.11 installs with an update key configured reject a signed manifest that sets it (`ERR_UPDATER_MANIFEST_SIGNATURE_INVALID`), the same way alpha.8 treats a signed `files[].blockMapUrl`. `UpdateInfoAndProvider` gains `manifestSignatureVerified`, and `BaseUpdater.verifyInstallerSignatureOnLaunch` receives the update info the cached installer was matched against. PowerShell is started by absolute path, the installer path is passed in an environment variable, and non-ASCII output is escaped instead of setting a console encoding, so verification works under PowerShell Constrained Language Mode (fixing 7.0.0-alpha.8 to alpha.10). The build-time installer check uses the same invocation. builder-util-runtime adds `prepareAuthenticodeSignatureExec` and `POWERSHELL_ASCII_ESCAPE_FUNCTION`. Migration: where PowerShell may be blocked (AppLocker / WDAC), assign a native `verifyUpdateFileAuthenticodeSignature` in your first electron-updater 7 release — see https://www.electron.build/docs/migration/v27-runtime-changes#windows-update-signature-verification-fails-closed
